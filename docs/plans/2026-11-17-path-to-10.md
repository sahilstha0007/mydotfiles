# Terminal Stack — Path to 10/10 Implementation Plan

> **Goal:** Raise the stack from a verified 7.5/10 toward 10/10 through genuine fixes and tuning. Each task names exact files, the gate that proves it, and the score axis it moves. Honest ceiling called out where an axis can only reach 9+ by removing a feature the user wants.

**Architecture:** The stack is a git repo (`~/mydotfiles`) stowed into `~/.config/*` via symlinks. Live processes read those symlinks. ML4W is a SEPARATE dotfiles repo (`~/.mydotfiles/com.ml4w.dotfiles.stable`) whose running daemon (`gtk-theme-switcher.sh`) invokes bare `matugen` and can re-seize `~/.config/matugen`. Multi-agent work must use disjoint file ownership.

**Tech Stack:** zsh/oh-my-zsh, kitty, wezterm (Lua), tmux, nvim/lazy.nvim, matugen, oh-my-posh, pytest-style shell/Lua test gates.

## Work list (priority order, each = one agent task)

### W1 — CRITICAL: make matugen config durable (theme + kitty + prompt Integration & Correctness)
- **Root cause:** `~/.config/matugen` symlink points at ML4W repo; its `config.toml` lacks the kitty sanitizer hook → `matugen` (run by ML4W daemon + our sync-wallpaper) writes invalid `/* */` CSS comments into `~/.config/kitty/colors-matugen.conf`, breaking `kitty config parse` / `collisions` / `sanitize` / `matugen hook` / `install doctor` gates (5 fails measured).
- **Files:** `install.sh`, `bin/stack-reload`, possibly a new watcher; ML4W daemon is EXTERNAL (do not edit).
- **Approach:** durable repoint + a guard that re-asserts on theme switch; OR make our sanitizer tolerate ML4W output. Do NOT edit the external ML4W repo.
- **Gate:** `bin/devcheck` back to 40/40; `kitty config parse` green; symlink survives a simulated ML4W theme switch.
- **Moves:** theme Integration 5→9, theme Correctness 6→8, kitty Integration 6→9, prompt Correctness 6→8. **Biggest single lever (~7.5 → ~8.2).**

### W2 — prompt (OMP) layer 6.5 → 8+ (lowest layer)
